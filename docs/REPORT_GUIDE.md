# 报告使用与数据来源

## 无需模型额度的本地使用
在项目根目录运行 README 中的报告命令，双击生成的 HTML。页面完全离线，不加载外部字体、图片或脚本。可用浏览器打印功能保存为 PDF。

## 三个演示案例
- latest-quotes.json：2026-10-17 12:32 WorkBuddy 调用记录整理的报价，非当前实时价格；两个组合超预算，无糖属性待确认，不计算节省。
- demo-quotes.json：虚构基线22元、用券加购24元，多花2元。
- demo-saving.json：虚构基线22元、满足相同需求的用券方案20元，少花2元。

模拟案例只能展示算法，不能作为真实券能力的证明。

## 新报价输入约定
参考 latest-quotes.json。context 标识门店、就餐方式和同一轮查询；每个报价必须使用相同上下文。price_data.price 为实际应付整数分，不使用划线价或商品单价推算代替。business_success 由调用方检查工具和业务状态，evidence_ref 指向脱敏依据。当前适配器不能独立验证这两个标记的真实性。

meets_needs=true 表示已确认满足原始餐品及口味要求；false 表示明确不符合；null 表示无法核实。预算由代码另算。baseline 可以为空，不能为了计算节省强行填入不符合要求的方案。extra_items 列出相对原需求的额外餐品。

report 中的 need、store_label、queried_at、data_label、evidence 为人工填写的脱敏展示文字。不要复制包含凭证、私人位置或券码的原始工具响应。渲染器转义文本但不识别私人信息，提交前仍需检查内容。

## 同款商品的价格差与需求匹配
coupon-verified-quotes.json 使用 price_reference 保存不用券的同款报价，通过 basket_items 的商品、数量、特制选择及同一查询上下文匹配后，输出 same_basket_saving_fen。此字段只说明买同样商品少付多少，不证明无糖等要求满足。属性待确认时 saving_fen 仍为空，不冒充有效需求基线。

## 展示调整
默认演示使用coupon-price-only.json：同一真实报价，展示指定餐品的用券前后价格，不沿用早期测试的无糖约束。原始coupon-verified-quotes.json保持不变，用于验证需求属性待确认的行为。只有用户明确提出对应要求，报告才显示该要求的待确认提示。

页面采用红色顶栏、黄色优惠强调、白底账单和灰色页面背景；为独立参赛项目，不使用官方商标或冒充官方点餐入口。来源及技术说明收纳到可展开区域。
