# 查询与报价

工具名仅作发现线索，以宿主返回的 schema 为准；不要照抄历史编码。

1. query-nearby-stores：按用户城市/商圈寻找门店，让用户确认具体门店和就餐方式。
2. query-meals：查询该门店菜单，按用户范围粗筛。名称不能证明糖含量、营养或精确规格；用户未提这些约束时不引入额外条件。
3. query-meal-detail：按需获取编码、默认选配与规格。缺少必需字段不猜填。
4. query-store-coupons：查询本门店适用的已有券。若需要确认卡包，按实际可用 schema 使用 query-my-coupons。available-coupons 可能只表示“可领取”，不能把它当已领取或门店可用，不调用 auto-bind-coupons。
5. calculate-price：同门店、方式和一轮上下文，分别核验不带券和带券的请求。工具层成功不等于业务成功，检查实际返回的成功标记和金额字段；不把菜单加总回退成已核验报价。

按 schema 选择已取得的 couponId/couponCode 与对应餐品，不假定可叠加。完整券标识只用于工具参数，不能放进公开报告或收藏。

报价均以整数分计算，特别检查金额单位，不因字段名猜测单位。结果同时标注时间与来源。用户选定了确切餐品、且未另提未确认口味要求时，才能认定对应需求已确认。

真实历史示例：2026-10-17 世界城广场餐厅到店自取，麦香鸡＋中杯冰美式，不用券2840分、用券2640分，券额外少付200分；预算2500分仍超140分。这不是当日所有组合的最低价，也不代表现在能买到。证据：https://github.com/bigjiaoniu/mcd-smart-choice/blob/main/docs/MCP_COUPON_RUN_03.md 。
